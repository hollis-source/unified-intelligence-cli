## Technical Deep Dive: Token Tracking

### Problem Statement
All 40 tasks in Baseline V1 showed 0 tokens. Initial hypothesis: metrics collection bug.

### Investigation Process
**4 Hypotheses Tested:**

1. **Hypothesis 1:** Metrics harness parsing bug
   **Test:** Manual CLI execution with `--collect-metrics`
   **Result:** ❌ No token data in stdout/stderr

2. **Hypothesis 2:** Metrics stored in files
   **Test:** Inspect `data/metrics/session_*.json`
   **Result:** ❌ `model_metrics` array empty

3. **Hypothesis 3:** Provider doesn't return tokens
   **Test:** Review `src/adapters/llm/grok_adapter.py`
   **Result:** ❌ Adapter only returns `result["response"]` string

4. **Hypothesis 4:** GrokSession doesn't capture tokens
   **Test:** Review `scripts/grok_session.py`
   **Result:** ✅ **ROOT CAUSE** - doesn't extract `usage` from API response

### Root Cause Analysis
**Data Flow:**
```
┌─────────────────────────────────────────────────────────────────────┐
│ XAI Grok API                                                        │
│ Returns: {                                                          │
│   "choices": [...],                                                 │
│   "usage": {                         ← TOKEN DATA HERE              │
│     "prompt_tokens": 123,                                           │
│     "completion_tokens": 456,                                       │
│     "total_tokens": 579                                             │
│   }                                                                 │
│ }                                                                   │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│ scripts/grok_session.py:GrokSession.send_message()                 │
│                                                                     │
│ response = await client.chat.completions.create(...)               │
│ return {                                                            │
│     "response": response.choices[0].message.content,                │
│     "tool_calls": [...]                                             │
│ }                                       ← USAGE DISCARDED ❌        │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│ src/adapters/llm/grok_adapter.py:GrokAdapter.generate()            │
│                                                                     │
│ result = self.session.send_message(...)                            │
│ return result["response"]            ← ONLY STRING RETURNED ❌      │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│ scripts/metrics_harness.py:run_agent_task()                        │
│                                                                     │
│ # Tries to parse stderr for JSON                                   │
│ if result.stderr:                                                   │
│     usage = json.loads(result.stderr)  ← NO DATA IN STDERR ❌       │
│                                                                     │
│ return {"tokens": 0}                                                │
└─────────────────────────────────────────────────────────────────────┘
```

**Conclusion:** Not a bug - **token tracking never implemented**.

## Lessons Learned

### Architecture Insight: Incomplete Abstractions
**Problem:** Token usage "fell through the cracks" between layers.
- XAI API returns usage → GrokSession discards
- GrokSession returns dict → GrokAdapter extracts only string
- Interface expects string → Metadata has no path

**Root Cause:** Interface too simple (`str`) for real needs (`str` + metadata).

**Prevention:** Define interfaces with extensibility in mind:
```python
# Bad (too simple)
def generate() -> str

# Good (extensible)
def generate() -> Dict[str, Any]  # Can add metadata without breaking

# Better (explicit)
@dataclass
class GenerationResult:
    content: str
    usage: TokenUsage
    tool_calls: List[ToolCall]
    metadata: Dict[str, Any]

def generate() -> GenerationResult
```
