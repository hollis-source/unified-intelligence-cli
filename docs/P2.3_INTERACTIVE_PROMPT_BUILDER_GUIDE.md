# P2.3 Interactive Prompt Builder - User Guide

**Feature**: Interactive PromptStrategy Builder with Domain-Specific Suggestions
**Status**: Production Ready ✅
**Version**: 1.0
**Date**: October 20, 2025

---

## Overview

The Interactive Prompt Builder is a guided CLI tool that helps you create high-quality PromptStrategy objects following the 4-Sentence Framework (Persona, Goal, Task, Context) with real-time validation and domain-specific suggestions.

**Key Benefits:**
- ✅ Lower barrier to creating high-quality prompts
- ✅ Real-time feedback with quality scoring (0-100)
- ✅ Domain-specific guidance (12 domains supported)
- ✅ Multiple output formats (YAML, JSON, Python)
- ✅ Validation prevents low-quality prompts (<60 score)

---

## Quick Start

### Basic Usage

```bash
# Interactive mode (default: YAML output)
python3 scripts/create_prompt.py

# JSON output with custom min score
python3 scripts/create_prompt.py --format json --min-score 70.0

# Python dict output
python3 scripts/create_prompt.py --format python

# Help
python3 scripts/create_prompt.py --help
```

## Interactive Workflow

### Step 1: Select Domain

Choose from 12 available domains:

1. **frontend** - UI/UX, React, Vue, Angular, CSS, HTML, component design
2. **backend** - API, REST, GraphQL, databases, servers, microservices
3. **testing** - Unit tests, integration tests, E2E, pytest, coverage (technical focus)
4. **qa** - Acceptance testing, BDD, Gherkin, exploratory, test planning (user/product focus)
5. **research** - Investigation, analysis, documentation, architecture decisions
6. **devops** - CI/CD, deployment, Docker, Kubernetes, infrastructure, monitoring
7. **security** - Authentication, encryption, vulnerabilities, OWASP, audits
8. **performance** - Optimization, profiling, benchmarking, latency, scalability
9. **documentation** - README, user guides, API docs, tutorials, changelogs
10. **dsl** - Parser, AST, interpreter, .ct files, workflow execution
11. **category-theory** - Mathematical foundations, formal verification, type theory
12. **general** - Cross-domain or unspecified tasks

**Selection Methods:**
- Enter number (1-12)
- Enter domain name (e.g., "backend")
- Press Enter for default ("general")

### Step 2: Enter Persona (WHO)

Define the agent's role, expertise level, and skills.

**Examples for Backend Domain:**
- "Senior Backend Engineer with 5+ years Python and FastAPI experience"
- "Database Specialist focusing on query optimization and schema design"
- "Lead Backend Architect with microservices and distributed systems experience"

**Guidelines:**
- Specify expertise level (Junior, Senior, Lead, etc.)
- Mention relevant skills and experience
- Be specific about domain knowledge

### Step 3: Enter Goal (WHAT - Measurable Outcome)

Define success with specific, measurable criteria.

**Suggested Metrics (Backend):**
- API response time p95 <100ms
- Database query time <50ms
- Error rate <0.1%
- Throughput >1000 requests/second

**Guidelines:**
- Include numeric targets (>90% coverage, <50ms latency, etc.)
- Specify measurable outcomes
- State the expected improvement or result

### Step 4: Enter Task (HOW - Concrete Actions)

Define specific actions to take.

**File Path Suggestions (Backend):**
- src/adapters/agent/*.py
- src/use_cases/*.py
- src/entity/*.py
- src/interface/*.py

**Tool Suggestions (Backend):**
- FastAPI
- SQLAlchemy
- Pydantic
- pytest

**Guidelines:**
- Include specific file paths (not just directories)
- Mention concrete tools and commands
- Provide code examples if relevant
- Break down into clear steps

### Step 5: Enter Context (WHY/WHEN/WHERE)

Provide background, constraints, and success criteria.

**Common Constraints:**
- Agent Tier: 2 (Lead) or 3 (Specialist)
- Previous interactions: 0 (or specify context)
- Backward compatibility required (no breaking changes)
- All existing tests must pass
- Code style: Follow PEP 8 / project conventions
- Documentation: Update relevant docs
- ULTRATHINK: Enabled (for complex tasks requiring deep analysis)

**Guidelines:**
- Specify agent tier level
- List available tools and resources
- Define constraints (backward compatibility, no breaking changes, etc.)
- Set success criteria (all tests pass, coverage >90%, etc.)
- Add ULTRATHINK directive if deep analysis needed

### Step 6: Validate & Review

The builder validates your prompt and shows:

**Quality Score:** 0-100 (based on specificity, clarity, completeness)

**Score Breakdown:**
- **Specificity:** File paths, numbers, code examples, tool names
- **Clarity:** Unambiguous language, clear structure
- **Completeness:** All 4 sentences present, context includes constraints/success criteria

**Validation Results:**
- ✓ PASSED (score ≥ threshold) - Ready to save
- ✗ FAILED (score < threshold) - Refinement suggested

**Improvement Suggestions:**
- Add file paths (e.g., src/routing/team_router.py:60-150)
- Include numeric constraints (e.g., p95 <50ms, coverage >90%)
- Provide code examples (e.g., functools.lru_cache(maxsize=1000))
- Specify concrete tools (e.g., cProfile, pytest-benchmark)

### Step 7: Save Prompt

Choose output format and save location.

**Output Formats:**

1. **YAML (default)** - Clean, human-readable
```yaml
persona: Senior Backend Engineer...
goal: Reduce API response time...
task: Profile src/adapters/agent/llm_executor.py...
context: |
  Agent Tier: 2 (Lead)
  Available tools: cProfile, pytest-benchmark
  ...
domain: backend
quality_score: 72.0
validation_passed: true
```

2. **JSON** - Machine-parseable, API-friendly
```json
{
  "persona": "Senior Backend Engineer...",
  "goal": "Reduce API response time...",
  "task": "Profile src/adapters/agent/llm_executor.py...",
  "context": "Agent Tier: 2...",
  "domain": "backend",
  "quality_score": 72.0,
  "validation_passed": true
}
```

3. **Python** - Direct import as dict
```python
"""Auto-generated prompt strategy."""

PROMPT_STRATEGY = {
    'persona': 'Senior Backend Engineer...',
    'goal': 'Reduce API response time...',
    'task': 'Profile src/adapters/agent/llm_executor.py...',
    'context': 'Agent Tier: 2...',
    'domain': 'backend',
    'quality_score': 72.0,
    'validation_passed': True
}
```

**ATADO Execution Command:**

After saving, the builder displays an ATADO command to execute your prompt:

```bash
python3 -m src.main \
  --task "$(cat prompts/backend_prompt_20251020_123456.yaml)" \
  --provider granite \
  --routing team \
  --agents scaled \
  --orchestrator simple \
  --collect-metrics \
  --timeout 120
```

## Advanced Usage

### Custom Minimum Score

Set a higher quality threshold:

```bash
python3 scripts/create_prompt.py --min-score 70.0
```

**Score Ranges:**
- **60-69:** Acceptable (default threshold)
- **70-79:** Good quality
- **80-89:** High quality
- **90-100:** Exceptional quality

### Non-Interactive Testing

For automated testing, mock user inputs:

```python
from src.cli.prompt_builder import PromptBuilder
from unittest.mock import patch

builder = PromptBuilder(min_score=60.0)

inputs = [
    'backend',  # domain
    'Senior Backend Engineer...',  # persona
    'Reduce latency...',  # goal
    'Profile and optimize...',  # task
    'Agent Tier: 2...',  # context
    'yes',  # accept validation
    '/path/to/output',  # output dir
    'yes'  # confirm save
]

with patch('click.prompt', side_effect=inputs):
    prompt = builder.build_interactive()
```

## Validation Scoring

### Specificity (40% weight)

**High Specificity Examples:**
- ✅ "Refactor src/routing/rag_team_router.py:60-150"
- ❌ "Refactor the routing code"

- ✅ "Reduce p95 latency from 150ms to <50ms"
- ❌ "Make it faster"

- ✅ "Use functools.lru_cache(maxsize=1000)"
- ❌ "Add caching"

### Clarity (30% weight)

**High Clarity Examples:**
- ✅ "Profile the execute() method to identify bottlenecks"
- ❌ "Look at performance stuff"

- ✅ "Implement connection pooling with SQLAlchemy"
- ❌ "Improve database things"

### Completeness (30% weight)

**Complete Prompt:**
- All 4 sentences present (Persona, Goal, Task, Context)
- Context includes constraints
- Context includes success criteria
- ≥50 words per section

## Troubleshooting

### Low Quality Score

**Problem:** Validation score below threshold (e.g., 48/100)

**Solutions:**
1. Add specific file paths (not just directories)
2. Include numeric targets (e.g., >90% coverage)
3. Provide code examples (e.g., `@lru_cache`)
4. Specify concrete tools (e.g., pytest, cProfile)
5. Add measurable success criteria

### Validation Failed

**Problem:** Prompt validation fails

**Solutions:**
1. Review improvement suggestions
2. Add missing elements (file paths, metrics, tools)
3. Increase specificity with concrete examples
4. Ensure all 4 sentences are present
5. Add ULTRATHINK directive for complex tasks
